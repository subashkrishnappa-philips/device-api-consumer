# device-api-consumer

Pact consumer tests for [`device-api`](../device-api). Owned and operated by the **Mobile Device Management Team**.

---

## Purpose

This repository contains the consumer-side pact tests that define the contract between this team's application and the `DeviceApi` service. Running these tests:

1. Verifies our code calls `DeviceApi` correctly (request shapes, status codes, response bodies).
2. Generates a pact file (`contracts/DeviceApi-Consumer-DeviceApi.json`) that is published to the provider CI so the provider can verify it hasn't broken our expectations.

## GitHub Actions Pipeline

Defined in [`.github/workflows/consumer-contract-tests.yml`](.github/workflows/consumer-contract-tests.yml).

### Triggers

| Event | When |
|---|---|
| `push` | Every push to `main` or `develop` |
| `pull_request` | Every PR targeting `main` or `develop` |

### Jobs

```
build ──► generate-pacts
```

| Job | What it does |
|---|---|
| `build` | `dotnet restore` + `dotnet build DeviceApi.Consumer.sln` |
| `generate-pacts` | Runs consumer tests → uploads `contracts/*.json` as artifact `pact-contracts` → dispatches `pact-contracts-updated` event to `device-api` repo |

### Artifact

After each successful run on `main`, the artifact **`pact-contracts`** (retained 90 days) is available for the provider CI to download and verify against.

### Cross-repo trigger

On every `main` push, the pipeline fires a `repository_dispatch` event to `device-api`, automatically triggering provider verification. No manual steps required.

### Required secrets

| Secret | Usage |
|---|---|
| `PROVIDER_REPO_TOKEN` | PAT with **Actions: write** on `device-api` — used to trigger the provider verification pipeline |

## Local Development

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)

### Run consumer tests

```powershell
.\run-consumer-tests.ps1
```

Or directly:

```powershell
dotnet test DeviceApi.Consumer.sln --configuration Release
```

The generated pact file will be written to `contracts/DeviceApi-Consumer-DeviceApi.json`.

## Adding or Changing Consumer Interactions

All interactions are defined in [`tests/DeviceApi.Consumer.Tests/Contracts/DeviceApiConsumerTests.cs`](tests/DeviceApi.Consumer.Tests/Contracts/DeviceApiConsumerTests.cs).

When the provider team adds new endpoints, they will:
1. Run their `SwaggerPactGenerator` tool.
2. Place generated stub files in `tests/DeviceApi.Consumer.Tests/Generated/`.
3. Open a PR or send a notification.

Your job is to:
1. Review the stubs in `Generated/`.
2. Move completed interactions into `Contracts/DeviceApiConsumerTests.cs`.
3. Push — the pipeline publishes updated pacts and triggers provider re-verification.

## Contract Compatibility

| Consumer Version | Compatible Provider |
|---|---|
| `main` | `device-api` `main` |

The contract is enforced by the provider's CI. If a provider change breaks a consumer interaction, the provider CI will fail and notify this team via the contacts in `device-api/contracts/consumers.json`.
